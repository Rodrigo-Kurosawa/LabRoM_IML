## 1. Project Overview

**LabRoM_IML** is a fork of the open-source [Weasis DICOM viewer](https://github.com/nroduit/Weasis) extended with an AI-powered **sex classification plugin** for skeletal remains. It targets forensic anthropology and bioarchaeology researchers: a researcher opens a DICOM series of a skeleton, clicks one button, and the system uses deep learning to determine biological sex from cranial/pelvic morphology — complete with Grad-CAM explainability heatmaps.

**Target users:** Researchers at LabRoM (Laboratório de Robótica e Manufatura), not general consumers.

**Deployment:** Ships as a self-contained Windows MSI. End users install it like any commercial app — no Java, Python, or command-line required.

**Upstream relationship:** Fork of `nroduit/Weasis`. The upstream Weasis modules (weasis-core, weasis-dicom, etc.) are **not modified** — only the custom plugin and build scripts are LabRoM code.

## 3. Key Source Files

### 3.1 `SexClassifierAction.java` — Pipeline Orchestrator

Entry point for the "Classify Sex" button. Runs the full 4-step pipeline asynchronously (SwingWorker) and builds the result UI.

**Pipeline steps:**
```
Step 1: DicomExtractor.extractSecondaryCaptures()  →  sc_0000.png, sc_0001.png, …
Step 2: PivotDetector.detectAndSaveWindow()        →  pivo_0000.png, … (±5 window)
Step 3: SexClassifier.classify()                   →  labels + heatmap PNGs
Step 4: buildComposites()                          →  comp_0000.png, … (side-by-side)
```

**Temp dir lifecycle — DO NOT change without understanding this:**
Temporary files (`sc_*.png`, `pivo_*.png`, heatmaps) live inside a temp directory created per pipeline run (`Files.createTempDirectory("sex_classifier_")`). These files **must NOT be deleted at pipeline end** because the result cards in the UI reference them for the entire Weasis session (image display, export).

Cleanup happens via a JVM shutdown hook registered once via a `static {}` block:

```java
private static final java.util.List<Path> TEMP_DIRS =
    new java.util.concurrent.CopyOnWriteArrayList<>();

static {
  Runtime.getRuntime().addShutdownHook(new Thread(() -> {
    for (Path dir : TEMP_DIRS) {
      try {
        Files.walk(dir)
            .sorted(java.util.Comparator.reverseOrder())
            .map(Path::toFile)
            .forEach(java.io.File::delete);
      } catch (Exception ignore) {}
    }
  }, "sex-classifier-cleanup"));
}
```

And in `runPipeline()`:
```java
tmpDir = Files.createTempDirectory("sex_classifier_");
TEMP_DIRS.add(tmpDir);
```

If you add cleanup at pipeline-end (e.g., in a `finally` block), the UI will display broken images.

**Composite image format:**
- Top bar: navy (male) or wine-red (female) with overall label
- Left: original pivot frame (max 700px wide)
- Right: Grad-CAM heatmap (max 700px wide)
- Bottom: frame index, per-frame label, confidence %
- Max width 1920px

### 3.2 `SexClassifier.java` — YOLOv8 Wrapper

Calls `sex_classify.py` via `ProcessBuilder`. Key constant:

```java
private static final String MODEL_FILENAME = "final.pt";
```

**This was changed from `"best.pt"` to `"final.pt"` in the `windows-compat` branch.** If you see the model not loading, verify this constant.

**Python process protocol (stdout):**
```
IMG:<idx>\t<label>\t<prob>\t<heatmap_path>   ← per-frame result
FINAL:<label>\t<prob>                         ← aggregated result
FAIL:<reason>                                 ← non-fatal per-image error
```

Timeout: 300 seconds. Process destroyed on timeout.

### 3.3 `DicomExtractor.java` — DICOM Secondary Capture Extraction

Pure-Java DICOM reader (no dcm4che3 at runtime). Detects Secondary Capture (SC) files by checking the 4-byte DICM magic at offset 128, then scanning for SOPClassUID / Modality tags.

Pixel extraction falls back to `dicom_extract_pixels.py` for compressed transfer syntaxes (JPEG, JPEG2000, JPEG-LS).

**Python search order (critical for distribution):**
1. `<appDir>/python-runtime/` — embedded Python from MSI
2. `~/.weasis/labrom-env/` — developer venv
3. System PATH
4. Absolute paths for Homebrew, pyenv

**Diagnostic counters** (read by SexClassifierAction for error messages):
- `DicomExtractor.lastTotal` — files scanned
- `DicomExtractor.lastDicom` — DICOM files found
- `DicomExtractor.lastSc` — SC files found
- `DicomExtractor.lastPixOk` — successfully extracted PNGs

### 3.4 `PivotDetector.java` — ResNet-50 Pivot Detection

Calls `pivo_inference.py` to score each frame. Picks the highest-probability frame as the pivot, then extracts a `WINDOW_RADIUS = 5` window (±5 frames) around it.

Fallback: if the Python call fails or `pivo.pt` is missing, uses the centre frame (`list.size() / 2`). Degraded but functional.

### 3.5 Python Scripts (bundled in JAR, extracted to temp at runtime)

| Script | Model | Task | Exit protocol |
|---|---|---|---|
| `dicom_extract_pixels.py` | none | Decode DICOM pixels → PNG | `OK:<path>` or `FAIL:<reason>` per line |
| `pivo_inference.py` | `pivo.pt` (ResNet-50) | Score pivot probability per frame | `<index> <prob>` per line |
| `sex_classify.py` | `final.pt` (YOLOv8) | Classify sex + Grad-CAM heatmaps | `IMG:<i>\t<label>\t<prob>\t<heatmap>` then `FINAL:<label>\t<prob>` |

All scripts exit 0 on per-image failures (emitting `FAIL:` lines). Only critical failures (missing `torch`) exit 1.

### Developer Build (`run_weasis.ps1`)

```
Phase 1: Validate bin-dist exists, detect JDK + WiX

```

Output: `dist-output/LabRoM_IML-x86-64.msi`

## 5. Runtime Behavior

### Application Launch (MSI-installed)

```
Weasis.exe
  └─ runtime/bin/java.exe
       └─ weasis-launcher.jar (AppLauncher)
            └─ felix.jar (OSGi framework)
                 ├─ weasis-core-*.jar
                 ├─ weasis-dicom-*.jar
                 └─ weasis-sex-classifier-*.jar  ← discovered via OSGi DS
                      └─ SexClassifierToolFactory → registers toolbar + panel
```

**Configuration name:** The app is renamed to "LabRoM_IML" by patching `conf/base.json` during `run_weasis.ps1`. The installer still shows "Weasis" branding (this is a known gap — see Section 8).

### Classification Pipeline at Runtime

When the user clicks "Classify Sex":

1. `SexClassifierAction.runPipelineAsync()` starts a `SwingWorker`
2. `SwingWorker.doInBackground()` calls `runPipeline()`:
   - Creates temp dir, registers it for shutdown cleanup
   - Calls `DicomExtractor` → PNG files in temp dir
   - Calls `PivotDetector` → identifies pivot frame, extracts ±5 window
   - Calls `SexClassifier` → YOLOv8 labels + heatmaps
   - Calls `buildComposites()` → side-by-side composite images
3. `SwingWorker.done()` fires callback on EDT → updates `SexClassifierTool` panel
4. Panel scrolls through result cards (composite images + text)

### OSGi Plugin Registration

The plugin is an OSGi bundle. Two factory classes use OSGi Declarative Services annotations:

- `SexClassifierToolFactory` — registers the dockable side panel
- `SexClassifierToolBarFactory` — registers the toolbar button

Both annotated with `@Component`, discovered at runtime via `OSGI-INF/*.xml` generated by `bnd-maven-plugin`.

## 7. Known Constraints and Gotchas

### 7.1 `weasis-native` Is Not a Git Repo — NEVER Edit Files There Directly

`../weasis-native/` is a directory generated by `run_weasis.ps1` from `weasis-native.zip`. It is not tracked by git. Any file you edit inside it will be **overwritten** on the next `run_weasis.ps1` run.

**The correct pattern:** Store the canonical version of a file inside `LabRoM_IML/` (which IS the git repo), then have `distribute.ps1` or `run_weasis.ps1` copy it into `weasis-native/` before use.

Example: `build/msi/x86-64/main.wxs` and `build/msi/aarch64/main.wxs` live in `LabRoM_IML/` and are copied over `weasis-native/build/script/resources/windows/msi/*/main.wxs` by `distribute.ps1`.

### 7.2 WiX3 vs WiX4 — main.wxs Must Be WiX3 Format

`jpackage` applies an XSLT transformation (`wix3-to-wix4-conv.xsl`) to convert a WiX3 `main.wxs` to WiX4 before handing it to `wix.exe`. The file in `build/msi/*/main.wxs` **must be in WiX3 format**:

```xml
<Product Id="$(var.JpProductCode)" ...>
  <Package InstallerVersion="$(var.JpInstallerVersion)"
           Compressed="$(var.JpCompressedMsi)"
           InstallScope="$(var.JpInstallScope)" />
  ...
</Product>
```

**Do NOT** use WiX4 format (`<Package ... InstallerVersion="...">` without a separate `<Product>` element) and do NOT include `<Binary Id="JpCaDll" SourceFile="wixhelper.dll"/>` — WiX 4 removed that DLL and the reference causes `WIX0103: Cannot find the Binary file 'wixhelper.dll'`.

The `main.wxs` files are stored permanently in git at `build/msi/x86-64/main.wxs` and `build/msi/aarch64/main.wxs`. The copy step in `distribute.ps1` ensures they override whatever jpackage regenerates.

### 7.3 Python Embeddable — BOM Corruption in `.pth` File

The Python embeddable archive's `python312._pth` file must be edited to uncomment `import site` (enables pip and packages). PowerShell's `Set-Content -Encoding UTF8` writes a UTF-8 BOM (`\xEF\xBB\xBF`) at the start of the file, turning `python312.zip` into `﻿python312.zip`. Python then cannot find its standard library and crashes with:

```
No module named 'encodings'
```

**The fix** (already in `distribute.ps1`): use `[System.IO.File]::WriteAllLines` with `new System.Text.UTF8Encoding($false)` (the `$false` disables BOM).

### 7.4 Temp Directory Lifecycle

Temp directories created by the pipeline hold files referenced by the UI (thumbnails, composites, heatmaps). Do NOT add cleanup in a `finally` block at pipeline end — it will break the display. Cleanup is handled exclusively by the static JVM shutdown hook in `SexClassifierAction.java`.

### 7.5 MODEL_FILENAME is `final.pt`, Not `best.pt`

`SexClassifier.java` has:
```java
private static final String MODEL_FILENAME = "final.pt";
```

This was intentionally changed from `"best.pt"`. If the model fails to load, check this constant first. `distribute.ps1` copies all `*.pt` files so both are bundled, but the code only loads `final.pt`.

### 7.6 PowerShell vs Bash Syntax

Scripts on Windows use PowerShell. Key differences:
- Line continuation: `\` (bash) → `` ` `` (PowerShell)
- Path separators: PowerShell accepts both `\` and `/` but many external tools need `\`
- `2>&1` on native executables wraps stderr as ErrorRecord in PowerShell 5.1 — avoid
- `Set-Content -Encoding UTF8` writes BOM — prefer `[System.IO.File]::WriteAllText` for Python-consumed files

### 7.7 Git Push Credentials

The remote is `https://github.com/Rodrigo-Kurosawa/LabRoM_IML.git`. The local git config `user.name = Rodrigo-Kurosawa`. However, Windows Credential Manager may store credentials for the `Davi-nAraujo` GitHub account. If `git push` returns `403 Permission denied to Davi-nAraujo`:

```powershell
# Option 1: explicit username in remote URL
git remote set-url origin https://Rodrigo-Kurosawa@github.com/Rodrigo-Kurosawa/LabRoM_IML.git

# Option 2: clear stored credentials
# Control Panel → Credential Manager → Windows Credentials → remove git:https://github.com
# Then re-authenticate when prompted (use a Personal Access Token as the password)
```

### 7.8 JDK Detection in Scripts

Both `run_weasis.ps1` and `distribute.ps1` auto-detect the JDK in this priority:
1. `$env:JAVA_HOME`
2. `~/Java/jdk-*` (sorted descending, takes highest version)
3. `java.exe` in PATH

JDK 25+ is required. The bundled `jdk-26/` folder in the repo is for runtime reference (gitignored). If detection fails, pass `-Jdk <path>` to `distribute.ps1`.

### 7.9 Python Cache in distribute.ps1

Phase 5 (Python embeddable installation) is skipped if `python.exe -c "import torch"` exits 0 — indicating a previous successful install is cached at `%LOCALAPPDATA%\LabRoM\python-runtime`. First build takes 15–30 minutes (downloads ~2 GB). Subsequent builds are instant.

To force reinstall: delete `%LOCALAPPDATA%\LabRoM\python-runtime`.

```powershell

winget install Apache.Maven                       # 3.8+
```
